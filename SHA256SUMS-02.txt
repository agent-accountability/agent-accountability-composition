## Note on the date field

The top-level `date:` key was removed from the Markdown front matter (see the
front-matter fix in this commit): with no explicit date, kramdown-rfc/xml2rfc
stamp the render date, so the `.txt`/`.xml` above are frozen at build time
2026-09-13. A rebuild on a later day reproduces the text unchanged but stamps
a different date/expiry in the front matter and page footers, which changes
these checksums. This is intentional — it is what keeps `DOC_DATE_IN_PAST`
from recurring while no one has picked the actual posting date yet — but it
means these checksums authenticate *this recut's* committed files, not
"whatever `make` produces on any given day." When Steven sets the actual
posting date, the final pre-submission commit re-pins `date:` explicitly
(the same pattern commit 69422af used for -01) and gets its own fresh sheet.
